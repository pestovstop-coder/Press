# TASK 008 — выбор мебели и Ctrl-размещение

Дополнение к [TASK 007](TASK_007_STATES.md). Состояния IDLE / PLACING / MOVING,
управление B/Esc/R и ограничения размещения сохранены. Новых ассетов,
физических коллизий и запрета пересечений нет.

## Панель

Сохранены две штатные Button, рисующие собственный текст и обрабатывающие
клики в том же прямоугольнике. Их минимальная область — 260×44 пикселя,
по горизонтали они заполняют колонку; вся область, включая текст и отступы,
интерактивна. Отдельных накладываемых Label или ручных областей кнопок нет.
Служебные Label игнорируют мышь, контейнер колонки пропускает события,
панель и кнопки обрабатывают их штатным GUI Godot.

Защита `_over_panel()` теперь переводит координаты viewport через обратный
`get_global_transform_with_canvas()` в локальные координаты панели, вместо
сравнения viewport-точки с `get_global_rect()` в другой системе координат.
Это учитывает смещение/масштаб CanvasLayer. Константных поправок к Y нет.

Наблюдаемое пользователем смещение не удалось воспроизвести без Godot;
исправлены геометрия областей/согласование координат, но фактическое устранение
проблемы в окне ещё требует runtime-приёмки.

## Выбор видимых поверхностей

В предыдущем редакторе **нет CollisionShape3D, PhysicsBody3D, collision layers/masks
или физического raycast**. Выбор выполнялся лучом против AABB отдельных мешей.
Система коллизий не добавлялась: вместо этого используется пересечение луча
с реальными треугольниками `Mesh.get_faces()`, с учётом transform меша.

- Принимаются оба порядка вершин: выбор не зависит от winding/грани.
- Сравнивается расстояние в мировых координатах до ближайшего попадания.
- Меши комнаты (пол, стены, дверной проём) ограничивают видимый луч. Мебель
  за стеной не выбирается; проём остаётся открытым там, где нет геометрии.
- Существующий стол исключён из статических препятствий, но остаётся выбираемым.
- Пустота между ножками и пространство вне фасок не считаются поверхностью стола.
- Треугольники кешируются по Mesh-ресурсу; transform берётся при каждом клике.
  Проверка идёт только при выборе, не каждый кадр. Невидимые меши пропускаются.

Это только visual picking, не запрет установки предметов в стены или друг друга.
Ближайшая реальная поверхность определяет выбор, а не общий объём соседнего предмета.

## Ctrl + ЛКМ

Модификатор берётся из самого InputEventMouseButton и передаётся в подтверждение.

| Состояние | ЛКМ | Ctrl + ЛКМ |
|---|---|---|
| IDLE | Выбор мебели либо ничего на пустоте | То же |
| PLACING | Один новый экземпляр, затем IDLE | Новый экземпляр; оставить независимый preview в PLACING |
| MOVING | Подтвердить перемещение того же объекта, затем IDLE | То же, без клонирования и продолжения установки |

При Ctrl-размещении сохраняются тип, координаты и текущий поворот preview.
Каждый установленный экземпляр — отдельный Node3D с обычными материалами/тенями;
он регистрируется как мебель, но не становится `editing`. Ghost остаётся только
временным preview. R продолжает менять его угол. Esc удаляет только preview и
возвращает IDLE; уже установленные экземпляры сохраняются.

### Ручная приёмка — остаётся выполнить все 11 сценариев TASK 008

1. Кликнуть по тексту каждой кнопки: появляется правильный preview.
2. Кликнуть по свободному от текста месту кнопки: тот же результат, мебель не ставится.
3. Выбрать стол кликом сверху с исходной камеры.
4. Выбрать стол сбоку; проверить соседние объекты и невозможность выбора сквозь стену.
5. Поставить стол обычным ЛКМ: preview исчезает, IDLE.
6. Поставить стол Ctrl+ЛКМ: обычный стол остаётся, следующий preview активен.
7. Повторить Ctrl+ЛКМ минимум три раза в разных местах: три отдельных экземпляра.
8. Между размещениями нажать R: поворот сохраняется у следующего preview.
9. Esc: preview исчезает, три стола остаются.
10. Выбрать стол, переместить с R, отменить Esc: исходные transform/материалы/тени.
11. Переместить с Ctrl+ЛКМ: одно подтверждение, IDLE, без дубликата/нового preview.

## Орбитальная камера

`CameraRig` — точка обзора на плоскости пола. Дочерняя ортографическая Camera3D
остаётся в локальной позиции `(0,0,30)`. Изменение pitch/yaw поворачивает **rig**,
поэтому камера движется по сфере радиуса 30 м вокруг фокуса и смотрит на него,
а не вращается вокруг самой себя. Начальный фокус — `(0,0,0)`; панорамирование
перемещает эту точку, и дальнейшее вращение происходит вокруг неё. Выбор мебели
не меняет фокус автоматически.

| Управление | Действие |
|---|---|
| ПКМ + движение X | Yaw, 0,25°/пиксель, полный оборот с wrap −180…180° |
| ПКМ + движение Y | Pitch, 0,25°/пиксель, ограничен **−70…−20°**, roll=0 |
| MMB + движение | Прежнее перемещение фокуса в XZ с учётом текущего yaw |
| WASD / стрелки | Прежнее перемещение по экранным осям, обновляемым после вращения |
| Колесо / + / − | Прежний сглаженный ортографический zoom, size 6…26 |
| Home | Фокус `(0,0,0)`, pitch −35,26438968°, yaw 45°, size 16; сброс drag-флагов |

Высота камеры при разрешённых углах — примерно 10,26…28,19 м над полом.
Yaw не меняет фокус или радиус. При MMB/клавиатуре прежние ограничения фокуса
X ±6 м, Z ±4,25 м. Zoom меняет размер проекции, не высоту или направление.

Старт навигации обрабатывается через `_unhandled_input`, после UI. Отпускание
RMB/MMB перехватывается в `_input`, даже над панелью; потеря фокуса приложения
также сбрасывает drag-флаги. Если нажаты обе кнопки, жестом управляет последняя
нажатая. Нажатие ЛКМ при навигации поглощается до размещения; дополнительная
защита в placement проверяет `is_navigating()`, включая физические RMB/MMB.

## Динамическая видимость

Новый `scripts/wall_visibility.gd`, узел `Main/WallVisibility`. Модули остаются
прямыми детьми `TestRoom`; принадлежность задана `metadata/cutaway_side`.
Пол и мебель не размечены и не скрываются. Добавление новых архитектурных
модулей допускает явное назначение стороны без изменения picking.

Для ортографической камеры используется горизонтальная нормализованная
`camera.global_basis.z` — направление **к камере**, а не её мировая позиция.
Поэтому панорамирование не переключает стороны неожиданно.

- front (+Z): facing = direction.z;
- rear (−Z): facing = −direction.z;
- east (+X): facing = direction.x;
- west (−X): facing = −direction.x.

Внешняя сторона скрывается при facing > **0,12**, возвращается при facing < **0,04**.
В промежутке сохраняется предыдущее состояние: гистерезис около касательного
направления, а не прозрачность или временной fade.

Центральная перегородка двухсторонняя и закрывает один из кабинетов при боковом
взгляде. Она скрывается при `abs(direction.x)>0,18`, возвращается при `<0,10`:
при взгляде почти вдоль перегородки она остаётся полноценной видимой стеной.

Три задних угловых модуля размечены двумя сторонами (`rear_west`, `rear_shared`,
`rear_east`). Они скрыты **только когда скрыты обе прилегающие стороны**. Это
сохраняет непрерывность видимой задней стены при скрытой перегородке/боковине,
а не создаёт дыру в центре задней стены. Оконные части следуют rear, дверные
рамы и наддверные перемычки — front, без разрозненных «висящих» рам.

Пересчёт происходит сразу по сигналу камеры `view_changed` (orbit/Home) и при
старте; `_process` также синхронизирует видимость при внешнем изменении transform.
Отдельной кнопки обновления нет. При скрытии/показе ничего не удаляется.

### Четыре контрольных направления

Отсчёт поворота — от стартового yaw=45°, не от мировой оси Z.

| Поворот | Yaw | Скрыты основные стороны | Видимы противоположные стороны |
|---|---|---|---|
| 0° | 45° | front, east, shared | rear, west |
| +90° | 135° | rear, east, shared | front, west |
| +180° | 225° | rear, west, shared | front, east |
| +270° | 315° | front, west, shared | rear, east |
| +360° | 45° | Как при 0° | Как при 0° |

Угловые посты — по описанному выше правилу двух сторон. При yaw около 0°/180°
центральная перегородка снова показывается. В офлайн-цикле с шагом 0,25° каждый
модуль и скрывается, и появляется; исходная конфигурация восстанавливается.

## Picking и размещение

В проекте уже нет физической системы столкновений для этой архитектуры;
TASK 011 её не добавляет и не разрушает. Picking — прежние лучи по треугольникам
мешей. `room_occluders` продолжает содержать все архитектурные меши, включая
восстановленные перемычки; видимые стены по-прежнему останавливают луч.

Существующая `_mesh_ray_distance` возвращает INF, если `not is_visible_in_tree()`.
Скрытый модуль остаётся в scene tree/cache, но не блокирует выбор мебели.
После показа сразу снова участвует в occlusion; менять face_cache не требуется.

В placement изменена только защита подтверждающего ЛКМ: вместо проверки одной
MMB теперь `not camera.get_parent().is_navigating()`. Остальные исполняемые
выражения контроллера идентичны TASK 010 (проверяется статическим сравнением).
IDLE/PLACING/MOVING, шаг 0,5 м, блок/стол, R, Esc, перемещение и Ctrl+ЛКМ прежние.
Само RMB/MMB не создаёт, не выбирает и не подтверждает мебель.

**Не добавлялся запрет пересечений мебели со стенами/другой мебелью:** существующая
логика его не реализовывала, и TASK 011 её не расширяет. Ограничение габаритов
полом осталось прежним. Дефекты TASK 008 (hitbox панели и выбор верхних поверхностей)
**остаются открытыми**, несмотря на наличие проверочных сценариев.

## Свет и ограничения прототипа

Все параметры Environment и девяти источников, материалы и renderer сохранены
от TASK 010. Тени — только Sun. Разрешение карт и shadow bias/blur не увеличивались.
При `visible=false` скрывается и вклад меша в обычную отрисовку теней: отдельные
невидимые shadow-only копии здесь не создаются. Свет при переключении сторон,
ступенчатость краёв и контакт теней требуют отдельной визуальной проверки.

Это правило направлений для двух прямоугольных кабинетов, не ray-based occlusion
solver. Оно не учитывает произвольные здания, точную видимость каждого пикселя,
будущие высокие шкафы или особые планы. При почти касательном ракурсе видимость
зависит от гистерезиса. Оценка удобства обоих кабинетов при всех жестах остаётся
за ручной приёмкой в Godot.
